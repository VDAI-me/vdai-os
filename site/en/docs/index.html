PARTICIPANTS

One task keeps the agreement together

After accepting a personal invitation, open “My tasks”: expected outcome, owner, executor, deadline, success criteria and approved sources.

What participants do

Take an assigned task → ask questions in its discussion → attach a file or result link → submit for review → read the owner’s decision.

What owners can track

Who is working, where help is needed, what has been submitted and what needs a decision. General platform access does not open all projects: each project requires an explicit grant from the owner.

Where work is stored

Shared tasks, comments and results belong to one OS. Code stays in the existing repository. Personal chats, model accounts and full private context remain with each participant.

MODELS AND BRIDGE

Track execution, beyond a model name

The Desktop OS source already reads Bridge status, provider traces and resource metrics with source attribution. This public website is not connected to live telemetry.

01

Who is executing

Task and job version, agent, provider, model and role: executor or advisor. A model missing from the receipt is shown as UNKNOWN.

02

What is happening

Queued, running, waiting or failed; the last verified event and its timestamp. A stale event does not prove the model is currently working.

03

What was returned

A provider receipt, deliverable and result checks. Starting a run or receiving a response does not mean the work has been accepted.

04

Who accepted it

Independent review and the owner’s decision: accept, request changes or defer. Usage is shown from available metrics only; otherwise it is UNKNOWN.

Where to look in Desktop OS

In a build containing these components, open the exact Bridge task: “Resource weight” shows provider, model and measured usage; “Lease / heartbeat” shows execution freshness; the request trace shows each stage, actor and receipt. Verify your installed build separately.

What is available for Cursor

Local hooks already collect activity metadata: model, start, tools and completion. This does not demonstrate a delivered result, usage or acceptance. Binding these events to the exact task and shared OS view still needs verification.

This is the observability contract for shared OS. The full live workflow across two computers still needs verification. Model quota and active execution are separate indicators.
